<Badge variant="warning">planned</Badge>
この機能はまだありません。[短縮 URL](/short-url)
が判定データをどう扱うかを、作る前に約束として決めるための下書きです。
実装までに変わることがあり、変えるときはこのページを先に直します。

Message Editor の URL（`#d=`）は判定データをサーバーに送りません（[Message Editor のデータの取り扱い](/message-editor/data-handling)）。
短縮 URL は、判定データを **自組織がセルフホストしたサーバー** に暗号化して預けます。
Message Editor の約束はそのままで、短縮 URL のサーバーに預ける部分について、次のように約束します。

## どこに届き、どこに残るか

| 経路                                                 | 判定データ                                                                                                                                                                                               | テスト |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| 短縮 URL のサーバー（自組織の Cloudflare）           | **届きます。** 登録のときと開くときだけです。保存する前に暗号化します                                                                                                                                    | —      |
| CRE の運営者                                         | **届きません。** サーバーは自組織のものです。Message Editor に `editor.cre.run` を使う場合も、`#d=` はサーバーに送られません                                                                             | —      |
| データベース（D1）                                   | **暗号文だけが残ります。** 鍵は「サーバーの鍵」と「短縮 URL の ID」の両方から作ります。ID はデータベースに保存しないので、データベースを見ても、サーバーの鍵があっても読めません                         | —      |
| データベースのバックアップ（D1 の Time Travel）      | **暗号文が最長 30 日残ります。** 有効期限切れや削除の後も残りますが、短縮 URL がなければ読めません                                                                                                       | —      |
| リンクのプレビュー（Slack などの展開）・検索エンジン | **渡しません。** 短縮 URL は Cloudflare Access のログインの後ろにあり、展開するボットやクローラーはログイン画面までしか見られません。検索エンジンにも載せません（`noindex`）                             | —      |
| サーバーのログ（Workers Logs）                       | **残しません。** 判定データ・Secret・ログインした人のメールアドレスを、自分ではログに書きません。URL（ID を含む）は Cloudflare の呼び出しのログに残りますが、ID だけでは開けません（ログインが要ります） | —      |
| 監査ログ                                             | **残しません。** 残すのは、どのクライアントが・いつ・作ったか消したか・データの大きさだけです                                                                                                            | —      |
| Message Editor への遷移                              | **ブラウザの中だけで渡します。** 開いたページが `#d=` を付けて Message Editor に移ります。`#` 以降はサーバーに送られません                                                                               | —      |
| ブラウザの履歴                                       | **残ります。** 移った先の Message Editor の URL（判定データ全体を含む）が残ります。この URL はログインなしで開け、短縮 URL の期限が切れても履歴からは開けます                                            | —      |
| URL を貼ったチャット・チケット・メール               | **残ります。** 有効期限までは、URL を知っていて、組織のメールアドレスでログインできる人が内容を読めます                                                                                                  | —      |
| ドメインのアクセスログ・社内のプロキシのログ         | **ID が残ることがあります。** ID は URL のパスに入るので、記録する設定にしているとそこに残ります。ID だけでは開けません（組織のメールアドレスでのログインが要ります）                                    | —      |

短縮 URL を開けるのは、組織のメールアドレスでログインした人だけです。組織の中の人なら、URL を知っていれば判定データ（問い合わせ本文・宛名・返信文・根拠の引用）を読めます。
実際のお客様の情報を含む短縮 URL は、社内の権限管理された場所にだけ貼ってください。

## 有効期限と削除

| 場面                                                                                            | どうなるか                                                                                                                                    | テスト |
| ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| 有効期限が切れたとき                                                                            | 開けなくなります。データベースからは自動では消さず、暗号文のまま残します（短縮 URL とサーバーの鍵の両方がないと読めません）。管理者が消せます | —      |
| 削除したとき                                                                                    | すぐに開けなくなり、データベースから消えます（バックアップには暗号文が最長 30 日残ります）                                                    | —      |
| 管理者がサーバーの鍵を変えたとき                                                                | それまでに作ったすべての短縮 URL が開けなくなります                                                                                           | —      |
| サーバーの鍵が設定されていないとき                                                              | 短縮 URL を作ることも開くこともできません。鍵なしで判定データを保存することはありません                                                       | —      |
| Cloudflare Access か、許可するメールのドメイン（`ALLOWED_EMAIL_DOMAINS`）が設定されていないとき | 短縮 URL を開けません。ログインなしで判定データを返すことはありません                                                                         | —      |
| 許可していないドメインのメールアドレスでログインしたとき                                        | 開けません。判定データは返しません                                                                                                            | —      |

## 受け付けない登録

| 受け付けない登録                                              | 扱い                                              | テスト |
| ------------------------------------------------------------- | ------------------------------------------------- | ------ |
| Secret がない・違う・無効にされたクライアントからの登録・削除 | 断ります。どれに当たるかは返しません              | —      |
| Message Editor が表示できないデータ                           | 登録しません（Message Editor と同じ検査をします） | —      |
| 圧縮データが 10 万文字を超える・展開後が 1 MB を超えるデータ  | 登録しません（Message Editor と同じ上限です）     | —      |
| 短い時間に多すぎる登録・読み出し                              | 断ります。少し待つと受け付けます                  | —      |

## 作成者について

自組織のドメインの短縮 URL は、管理者が Secret を発行したクライアントだけが作れます。
ただし、移った先の Message Editor は、短縮 URL から来たかどうかを区別しません。Message Editor の URL は誰でも作れるので、
短縮 URL を経由していない Message Editor の URL の内容は、[Message Editor のデータの取り扱い](/message-editor/data-handling)のとおり、出所を確かめてから使ってください。

## 確かめ方

まだ実装していないので、「テスト」列はすべて — です。
実装するときに、約束ごとにテスト（E2E か単体テスト）を書き、[Message Editor のデータの取り扱い](/message-editor/data-handling)と同じようにバッジを置きます。

実装した後もテストしない約束（予定）:

- ブラウザの履歴、URL を貼った先、ドメインのアクセスログや社内のプロキシのログに残ることは、ブラウザや外部のサービス・設定の振る舞いなので確かめません
- データベースのバックアップ（D1 の Time Travel）が 30 日残ることは Cloudflare の仕様なので確かめません。読めないこと（暗号文だけが残ること）はテストで確かめます
- CRE の運営者に届かないことは、セルフホストという構成によるもので、テストではなく本文に書いています
- Cloudflare Access のログイン画面と、ダッシュボードでの Access の設定は Cloudflare の側のものなので確かめません。Access を通っていない、または許可していないドメインのリクエストに、サーバーが判定データを返さないことはテストで確かめます
