この機能はまだありません。[短縮 URL](/short-url) を自組織の Cloudflare
で動かすための手順の下書きです。名前や手順は実装までに変わることがあります。

コマンドは `apps/short-url` で、`vp exec` を付けて実行します（`vp run` は環境変数を引き継がず、出力をキャッシュするため使いません）。

## 1. データベースを作る

```bash
vp exec wrangler d1 create short-url                      # 表示された database_id を wrangler.jsonc に書く
vp exec wrangler d1 migrations apply short-url --remote   # テーブルを作る（更新のたびにも実行する）
```

## 2. `wrangler.jsonc` を書き換える

| 項目                         | 書くもの                                                                                            |
| ---------------------------- | --------------------------------------------------------------------------------------------------- |
| `name`                       | Worker の名前                                                                                       |
| `routes`                     | 短縮 URL のドメイン（Cloudflare で管理しているゾーンのもの）                                        |
| `d1_databases`               | 1 で作ったデータベースの名前と `database_id`                                                        |
| `vars.ALLOWED_EMAIL_DOMAINS` | **必須。** 短縮 URL を開けるメールアドレスのドメイン（例: `example.com`）。カンマ区切りで複数       |
| `vars.ACCESS_TEAM_DOMAIN`    | **必須。** Cloudflare Access のチームのドメイン（例: `example.cloudflareaccess.com`）。5 で確かめる |
| `vars.ACCESS_AUD`            | **必須。** Access のアプリケーションの AUD タグ。5 でかけた Access の画面からコピーする             |
| `vars.EDITOR_URL`            | 移る先の Message Editor。書かなければ `https://editor.cre.run/`                                     |

秘密の値は、ここには書きません（`wrangler.jsonc` はリポジトリに入ります）。

## 3. サーバーの鍵を登録する

判定データを暗号化する鍵 `LINK_MASTER_KEY` を、Worker の Secret に登録します。値は画面にもシェルの履歴にも出しません。

```bash
node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('base64url'))" \
  | vp exec wrangler secret put LINK_MASTER_KEY
```

- 鍵がないあいだは、作ることも開くこともできません
- 鍵を変えると、それまでの短縮 URL はすべて開けなくなります（すべてを消したいときにも使えます）

## 4. デプロイする

`CLOUDFLARE_API_TOKEN` と `CLOUDFLARE_ACCOUNT_ID` を環境変数（CI ならシークレット）に入れて、デプロイします。
API トークンは、テンプレート「Edit Cloudflare Workers」に D1 の編集を足し、対象を 1 つのアカウントに絞って作ります。

```bash
vp exec wrangler deploy
```

## 5. Cloudflare Access をかける

短縮 URL を開けるのを、組織のメールアドレスでログインした人だけにします。Access は `wrangler.jsonc` では設定できないので、ダッシュボードで行います。

1. Worker の「Access」タブで「Protect this Worker behind Access」を選び、ポリシーに「メールアドレスのドメインが一致する」（2 の `ALLOWED_EMAIL_DOMAINS` と同じ）を設定します
2. Bot が使う `/api/` だけを外します。Zero Trust の「Access」→「Applications」で `short.example.com/api/*` のアプリケーションを作り、ポリシーを **Bypass** にします

3. 1 の Access の設定画面で「Application Audience (AUD) Tag」をコピーし、`vars.ACCESS_AUD` に書いて、もう一度デプロイします

サーバーは、Access がリクエストに付ける JWT（`Cf-Access-Jwt-Assertion` ヘッダー）の署名を確かめ、その中のメールアドレスのドメインが `ALLOWED_EMAIL_DOMAINS` に入っているときだけ判定データを返します。Access をかけ忘れたり、ポリシーを誤って広げたりしても、組織の外の人には開けません。

## 6. Bot に Secret を渡す

Bot ごとに Secret を発行します。Secret は一度だけ表示され、サーバーにはハッシュだけが残ります。

```bash
vp exec node scripts/clients.ts create slack-bot   # Secret（crs_…）を表示する
vp exec node scripts/clients.ts disable <ID>       # 使わなくなった・漏れたときに無効にする
```

Bot の側では、Secret をシークレットの管理機能か環境変数（例: `CRE_SHORT_URL_SECRET`）に置きます。

## 7. 確かめる

```bash
curl -i -X POST https://short.example.com/api/links
```

`401` が返れば、`/api/` が Access から外れていて、鍵も設定されています（Secret がないので断られた）。
`503` なら鍵か `vars` の必須の項目が、`302`（Access のログインへの転送）なら 5 の `/api/` の除外が、正しく設定されていません。

最後に、見本データで短縮 URL を 1 つ作り、組織のメールアドレスでは開け、外のメールアドレスでは開けないことを確かめてから削除します。

## ローカルで動かすとき

`apps/short-url/.dev.vars`（リポジトリに入れない）に、ローカル用に作った鍵とドメインを書きます。ローカルには Access がないので、テスト用の鍵で署名した JWT をヘッダーに付けて開きます（そのためのスクリプトは実装時に用意します）。

```dotenv
LINK_MASTER_KEY=<ローカル用に作った値>
ALLOWED_EMAIL_DOMAINS=example.com
ACCESS_TEAM_DOMAIN=localhost:8788   # テスト用の公開鍵を返すローカルのサーバー
ACCESS_AUD=short-url-dev
```

```bash
vp exec wrangler d1 migrations apply short-url --local
vp exec node scripts/clients.ts create dev --local
vp exec wrangler dev
```
