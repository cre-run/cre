この機能はまだありません。[短縮 URL](/short-url) を自組織の Cloudflare
で動かすときに、何をどこに設定するかを決めるための下書きです。
名前や手順は、実装までに変わることがあります。

## 設定するものの一覧

設定は 5 種類あり、それぞれ置き場所が違います。秘密のものをリポジトリやチャットに書かないよう、まずこの表で区別してください。

| 種類                                                                           | 置き場所                                   | 秘密か     | 名前                                            |
| ------------------------------------------------------------------------------ | ------------------------------------------ | ---------- | ----------------------------------------------- |
| [Worker の Secret](#worker-の-secret)                                          | Cloudflare（`wrangler secret put` で登録） | **秘密**   | `LINK_MASTER_KEY`                               |
| [Worker の環境変数](#worker-の環境変数)                                        | `wrangler.jsonc` の `vars`                 | 秘密でない | `EDITOR_URL`                                    |
| [`wrangler.jsonc` のそのほかの項目](#wranglerjsonc-で自組織のものに変える項目) | `wrangler.jsonc`                           | 秘密でない | Worker 名・ドメイン・データベース・レート制限   |
| [デプロイと管理に使う資格情報](#デプロイと管理に使う資格情報)                  | CI のシークレット、管理者の手元の環境変数  | **秘密**   | `CLOUDFLARE_API_TOKEN`・`CLOUDFLARE_ACCOUNT_ID` |
| [クライアントの Secret](#クライアントの-secret)                                | Bot など、短縮 URL を作る側                | **秘密**   | `crs_…`（Bot 側では例: `CRE_SHORT_URL_SECRET`） |

Worker（短縮 URL のサーバー）が動くときに読むのは、上の 2 つ（`LINK_MASTER_KEY` と `EDITOR_URL`）と `wrangler.jsonc` だけです。
`CLOUDFLARE_API_TOKEN` などは、デプロイや管理のコマンドが使うもので、Worker には登録しません。

コマンドは `apps/short-url` で実行します。`vp run` ではなく `vp exec` を使ってください。
`vp run` は環境変数をほとんど引き継がず（`CLOUDFLARE_API_TOKEN` が届かない）、出力をキャッシュするため、表示した Secret が手元のキャッシュに残ります。

## Worker の Secret

### `LINK_MASTER_KEY`（必須）

判定データを暗号化する鍵です。サーバーに 1 つだけ設定します。

| 項目                | 内容                                                                                                                                |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 使い道              | 判定データの暗号化と、短縮 URL の ID からデータを探すため                                                                           |
| 形式                | 32 バイトの乱数を base64url（`=` なし）にした 43 文字                                                                               |
| 設定していないとき  | 作る・開く・削除がすべてできません。API は `503`（`not_configured`）、開くページは「短縮 URL の設定が終わっていません」を表示します |
| 形式が違うとき      | 設定していないときと同じです                                                                                                        |
| 値を変えたとき      | それまでに作った短縮 URL が、すべて開けなくなります                                                                                 |
| なくしたとき        | Cloudflare からは読み出せません。新しく作って登録し直します（それまでの短縮 URL は開けなくなります）                                |
| PR ごとのプレビュー | 本番とは別の値を登録します                                                                                                          |

作って登録します。値は画面にもシェルの履歴にも出しません。

```bash
cd apps/short-url
node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('base64url'))" \
  | vp exec wrangler secret put LINK_MASTER_KEY
```

PR ごとのプレビューを使う場合は、別の値を作って登録します。

```bash
node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('base64url'))" \
  | vp exec wrangler preview base-config secret put LINK_MASTER_KEY
```

- 登録できたかは `vp exec wrangler secret list` で確かめます（名前だけが表示され、値は表示されません）
- `wrangler.jsonc` の `vars` には書かないでください。`wrangler.jsonc` はリポジトリに入ります
- 値を手で入力したり、`echo` の引数に書いたりしないでください。シェルの履歴に残ります
- 控えは要りません。なくしても、作り直せば短縮 URL をまた作れます。控える場合は組織のシークレット管理に置き、チャットやチケットに貼らないでください
- すべての短縮 URL を一度に開けなくしたいときも、この値を変えます

## Worker の環境変数

`wrangler.jsonc` の `vars` に書きます。秘密ではありません。

| 名前         | 必須 | 書かないとき              | 説明                                                                                                                                                                            |
| ------------ | ---- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `EDITOR_URL` | —    | `https://editor.cre.run/` | 短縮 URL を開いたあとに移る Message Editor の URL です。`https://` で始まり、`#` を含まない URL を書きます。形式が違うと、`LINK_MASTER_KEY` がないときと同じく `503` になります |

```jsonc
"vars": { "EDITOR_URL": "https://editor.example.com/" },
```

- 判定データは `#d=` に載せて渡すので、`EDITOR_URL` のサーバーには届きません
- Message Editor も自組織で動かしたいときは、自前でデプロイした Message Editor の URL を書きます

## `wrangler.jsonc` で自組織のものに変える項目

| 項目                                 | CRE のインスタンスの値          | 自組織で設定するもの                                                                                                                   |
| ------------------------------------ | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `name`                               | `cre-short`                     | Worker の名前                                                                                                                          |
| `routes`                             | `s.cre.run`（カスタムドメイン） | 短縮 URL のドメイン（Cloudflare で管理しているゾーンのもの）                                                                           |
| `d1_databases`                       | `cre-short`                     | `vp exec wrangler d1 create <名前>` で作ったデータベースの名前と `database_id`                                                         |
| `ratelimits[].namespace_id`          | —                               | アカウントの中で重ならない数（ほかの Worker のレート制限と同じ数にしない）                                                             |
| `previews.d1_databases`              | `cre-short-preview`             | PR ごとのプレビュー用のデータベース。プレビューを使わないなら消す                                                                      |
| `previews.ratelimits`                | —                               | プレビュー用のレート制限。プレビューは本番の設定を引き継がないので、本番と別の `namespace_id` で定義する。プレビューを使わないなら消す |
| `observability.logs.invocation_logs` | `false`                         | **`false` のままにしてください。** `true` にすると、URL に入る ID がログに残ります                                                     |

データベースを作り、テーブルを用意します。

```bash
vp exec wrangler d1 create short-url                       # 表示された database_id を wrangler.jsonc に書く
vp exec wrangler d1 migrations apply short-url --remote    # テーブルを作る（更新のたびにも実行する）
```

## デプロイと管理に使う資格情報

デプロイ、データベースの更新、Secret の登録、クライアントの発行で、wrangler が使います。Worker には登録しません。

| 名前                    | 使う場面                                | 置き場所                                                                 |
| ----------------------- | --------------------------------------- | ------------------------------------------------------------------------ |
| `CLOUDFLARE_API_TOKEN`  | CI でのデプロイ、手元での管理のコマンド | CI のシークレット。手元では環境変数（`vp exec wrangler login` でもよい） |
| `CLOUDFLARE_ACCOUNT_ID` | 同上（どの Cloudflare アカウントか）    | 同上                                                                     |

API トークンは、Cloudflare のダッシュボードでテンプレート「Edit Cloudflare Workers」から作り、次のように絞ります。

- 対象は、短縮 URL を動かす 1 つのアカウントだけにする
- D1 の編集の権限を足す（データベースの更新とクライアントの発行に使う）
- 短縮 URL のドメインのゾーンを対象に含める（カスタムドメインの設定に使う）

必要な権限の細かい内訳は、実装のときに実際にデプロイして確かめ、このページに書きます。

## クライアントの Secret

短縮 URL を作る Bot などに 1 つずつ発行します。Worker ではなく、Bot の側に置きます。

```bash
vp exec node scripts/clients.ts create slack-bot    # Secret（crs_…）が一度だけ表示される
vp exec node scripts/clients.ts list                # 発行したクライアントの一覧（Secret は表示されない）
vp exec node scripts/clients.ts disable <client_id> # 無効にする
```

- 表示された Secret は、Bot のシークレット管理か環境変数（例: `CRE_SHORT_URL_SECRET`）に入れます。名前は Bot の側で決めてかまいません
- サーバーにはハッシュだけが残るので、あとから表示し直すことはできません。なくしたら新しく発行します
- Bot ごとに別のクライアントにします。共有すると、1 つだけ無効にすることができません
- 入れ替えるときは「新しく発行する → Bot を切り替える → 古いものを無効にする」の順にします
- 漏れたときは、すぐに無効にします。漏れた Secret で短縮 URL を作ったり消したりはできますが、中身を読むことはできません

## ローカルで動かすとき

ローカルでは、`apps/short-url/.dev.vars` に書きます（リポジトリには入れません）。

```dotenv
LINK_MASTER_KEY=<ローカル用に作った値>
EDITOR_URL=http://localhost:4173/
```

- `LINK_MASTER_KEY` は、上と同じ手順でローカル用に新しく作ります。本番やプレビューの値を使わないでください
- クライアントは `vp exec node scripts/clients.ts create dev --local` で、ローカルのデータベースに発行します

## 設定を確かめる

Secret を付けずに登録を試すと、鍵が設定されているかが分かります。

```bash
curl -i -X POST https://short.example.com/api/links
```

| 返ってきたもの                        | 状態                                                         |
| ------------------------------------- | ------------------------------------------------------------ |
| `503` と `{"error":"not_configured"}` | `LINK_MASTER_KEY` か `EDITOR_URL` が正しく設定されていません |
| `401` と `{"error":"unauthorized"}`   | 鍵は設定されています（Secret を付けていないので断られた）    |

最後に、発行したクライアントの Secret で見本データの短縮 URL を 1 つ作り、開けることを確かめてから削除します（[短縮 URL を作る](/short-url#短縮-url-を作るbot連携の開発者向け)）。
見本データは、`apps/message-editor` で `node scripts/encode.ts` を実行して表示される URL の、`#d=` より後ろです。

## やってはいけないこと

- Secret（`LINK_MASTER_KEY`・クライアントの Secret・API トークン）を、`wrangler.jsonc`、リポジトリ、CI のログ、チャット、チケットに書く
- 本番の `LINK_MASTER_KEY` を、プレビューやローカルで使う
- `observability.logs.invocation_logs` を `true` にする
- PR ごとのプレビューに、実際のお客様の判定データを登録する
