[Message Editor](/message-editor) の URL は、判定データを `#d=` に載せるため長くなります（見本データで約 3,600 文字）。
Slack のボタンのように URL の長さに上限がある場所には、そのままでは載りません。
短縮 URL を使うと、同じ内容を `https://<自組織のドメイン>/<ID>` の短い URL で渡せます。

## できること

- Bot などの連携の仕組みが判定データを登録すると、短縮 URL が返ってきます
- 短縮 URL を開くと、組織のメールアドレスでログインしたうえで、Message Editor にその判定データが表示されます。開いたあとの画面と操作は、今の Message Editor と同じです
- 有効期限が来るか削除すると、短縮 URL は開けなくなります

短縮 URL のサーバーは、自組織の Cloudflare にセルフホストして使います（1 つの組織で 1 つ）。
短縮 URL を作れるのは、管理者が Secret を発行したクライアント（Bot など）だけです。誰でも作れる公開サービスではありません。
短縮 URL を開けるのは、Cloudflare Access で **組織のメールアドレス（ドメイン）でログインした人** だけです。URL が組織の外に漏れても、それだけでは開けません。

## URL の形

```text
https://short.example.com/0f8c3a52-6b1e-4d7a-9c25-3e4f5a6b7c8d
```

- ドメインは、セルフホストしたサーバーのドメイン（自組織のもの）です
- ID はランダムな UUID（v4）です。推測できません。開くには、URL を知っていることに加えて、組織のメールアドレスでのログインが要ります
- 長さは「ドメイン + 37 文字」で、判定データの大きさによらず一定です

| 渡し方                         | URL の長さ（見本データ）               | Slack のボタン（3,000 文字まで） |
| ------------------------------ | -------------------------------------- | -------------------------------- |
| Message Editor の URL（`#d=`） | 3,578 文字。判定データが増えると伸びる | 載りません                       |
| 短縮 URL                       | 62 文字（`short.example.com` の場合）  | 載ります                         |

## 開いたときの動き

1. 短縮 URL を開くと、まだログインしていなければ Cloudflare Access のログイン画面が出ます。組織のメールアドレスでログインします（ワンタイム PIN や、組織のシングルサインオン）
2. ログインすると、「Message Editor を開いています」と表示されます
3. ページがサーバーから判定データを受け取り、Message Editor（`https://editor.cre.run/#d=…`）に移ります
4. 移ったあとは、今の Message Editor と同じです。ブラウザの「戻る」で短縮 URL のページには戻りません

開けないときは、次のように表示します。

| 表示                               | 理由                                                                                | すること                             |
| ---------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------ |
| このリンクは開けません             | 有効期限が切れた、削除された、または URL が間違っている                             | 共有した人に、もう一度作ってもらう   |
| このメールアドレスでは開けません   | ログインしたメールアドレスのドメインが許可されていない                              | 組織のメールアドレスでログインし直す |
| 短縮 URL の設定が終わっていません  | 管理者がサーバーの鍵や、Cloudflare Access・許可するメールのドメインを設定していない | 管理者に連絡する                     |
| しばらくしてから開き直してください | 短い時間に多く開いた                                                                | 少し待ってから開き直す               |
| JavaScript を有効にしてください    | ブラウザで JavaScript が無効になっている                                            | JavaScript を有効にして開き直す      |

組織のメールアドレスでログインできないときは、Cloudflare Access の画面で止まり、短縮 URL のページは表示されません。

Slack などがリンクのプレビュー（展開）を表示しても、そこに判定データは出ません（展開するボットはログインできないため）。

## 有効期限

- 既定は **30 日** です。登録するときに、1 時間から 90 日までの間で指定できます
- 有効期限を過ぎると開けなくなります。サーバーのデータベースからは自動では消えず、暗号化されたまま残ります（管理者が消せます）
- 期限の前でも、Secret を持つクライアントが削除できます。削除するとすぐに開けなくなります
- 開いたあとの Message Editor の URL（判定データ全体を含む）は、ブラウザの履歴に残ります。短縮 URL の期限が切れても、履歴からは開けます

どこにデータが届き、どこに残るかは、[短縮 URL のデータの取り扱い](/short-url/data-handling)にまとめています。

## 短縮 URL を作る（Bot・連携の開発者向け）

管理者から受け取った Secret を付けて、判定データを登録します。
`data` には、Message Editor の URL の `#d=` より後ろと同じ値を入れます。

```bash
# link.json: {"data": "<#d= より後ろの値>", "expiresIn": 604800}
curl -X POST https://short.example.com/api/links \
  -H "Authorization: Bearer $CRE_SHORT_URL_SECRET" \
  -H "Content-Type: application/json" \
  --data-binary @link.json
```

```json
{
  "id": "0f8c3a52-6b1e-4d7a-9c25-3e4f5a6b7c8d",
  "url": "https://short.example.com/0f8c3a52-6b1e-4d7a-9c25-3e4f5a6b7c8d",
  "expiresAt": "2026-10-19T09:00:00.000Z"
}
```

- `expiresIn` は有効期限（秒）です。省略すると 30 日です
- Message Editor が表示できないデータ（形式が違う、圧縮データが 10 万文字を超える、展開後が 1 MB を超える、など）は登録しません
- 判定データをコマンドに直接書かず、ファイル（`@link.json`）から渡してください。シェルの履歴に残さないためです
- Secret はコードやリポジトリに書かず、環境変数やシークレットの管理機能に置いてください

削除するときは、ID を指定します。

```bash
curl -X DELETE https://short.example.com/api/links/0f8c3a52-6b1e-4d7a-9c25-3e4f5a6b7c8d \
  -H "Authorization: Bearer $CRE_SHORT_URL_SECRET"
```

## セルフホストする（管理者向け）

1. 自組織の Cloudflare に、短縮 URL の Worker とデータベース（D1）を作り、ドメインを割り当てます
2. Cloudflare Access で、短縮 URL を開けるメールアドレスのドメインを設定します（Bot が使う `/api/` は Access の対象から外します）。サーバーの設定（`ALLOWED_EMAIL_DOMAINS`）にも同じドメインを書きます。どちらかが欠けているあいだは、短縮 URL を開けません
3. サーバーの鍵を設定します。鍵がない、または形式が違うあいだは、短縮 URL を作ることも開くこともできません
4. クライアント（Bot など）ごとに Secret を発行して渡します。Secret は発行したときに一度だけ表示され、サーバーにはハッシュだけが残ります
5. 使わなくなったクライアントは無効にします。無効にした Secret では、作ることも削除することもできません

サーバーの鍵を変えると、それまでに作った短縮 URL は開けなくなります。すべてを消したいときは、鍵を変えたうえで、データベースからも消します（[セルフホストの設定](/short-url/self-hosting#link_master_key必須)）。

設定する Secret・環境変数・`wrangler.jsonc` の項目と、その設定のしかたは、[セルフホストの設定](/short-url/self-hosting)にまとめています。
