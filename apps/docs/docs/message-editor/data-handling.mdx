[Message Editor](/message-editor)
のプロトタイプ（editor.cre.run）が、判定データをどう扱うかをまとめています。 判定データを URL
以外で受け渡す仕組みができたら、このページを更新します。

## どこに届き、どこに届かないか

| 経路                                   | 判定データ                                                                                       |
| -------------------------------------- | ------------------------------------------------------------------------------------------------ |
| サーバー（Cloudflare）                 | **届きません。** URL の `#` 以降はブラウザがサーバーに送らないためです                           |
| 画面からの送信・外部サービスへの連携   | **行いません。** データはブラウザの中だけで復号・表示します                                      |
| ブラウザへの保存                       | **行いません。** 編集した本文は画面を閉じると消えます                                            |
| 根拠のリンクの遷移先                   | **渡しません。** リンクは新しいタブで開き、元の URL（判定データ）も `window.opener` も渡しません |
| ブラウザの履歴・ブックマーク           | **残ります**                                                                                     |
| URL を貼ったチャット・チケット・メール | **残ります。** URL を知っている人は誰でも内容を読めます                                          |

URL には判定データ（問い合わせ本文・宛名・返信文・根拠の引用）が圧縮されただけで、暗号化はされずに入っています。
実際のお客様の情報を含む URL は、社内の権限管理された場所にだけ貼ってください。

## 受け付けないデータ

次のデータは表示せず、見本データとエラーを表示します。

- 形式が合わないもの（必須の項目がない、段落 ID が重複している、など）
- 根拠のリンクが `http(s)` 以外のもの（`javascript:` などはリンクにしません）
- 圧縮データが 10 万文字を超えるもの、展開後が 1 MB を超えるもの（展開しながら大きさを見て、超えた時点で打ち切ります）

## 作成者を検証しないこと

URL は誰でも作れ、署名もありません。画面が「確認済み」と表示しても、それは URL に書かれていた値です。
出所の分からない URL の内容を根拠にしないでください。

## 確かめ方

これらの約束は `apps/message-editor` のテストで確かめ続けています。

- 画面のコードが、送信・保存する API（`fetch`・`localStorage` など）を使っていないこと。外部スクリプトを読み込まないこと
- 実際のブラウザで一通り操作しても、自分のオリジン以外に通信せず、ブラウザに何も保存しないこと
- 根拠のリンク先に、元の URL も `window.opener` も渡らないこと
- `javascript:` のリンク、大きすぎるデータ、展開すると大きくなるデータが、エラーになること
